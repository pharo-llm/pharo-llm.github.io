Use the models

Agents & tool use

Pharo-Coder is not only a code generator: it is an instruction-tuned assistant that can work as an agent, calling tools in a loop, reading the real results from a Pharo image, and continuing until the task is done.

What the agent can do

  • Explore the image: find which class implements a selector, read its source, browse a class.
  • Write code, try it with evaluate, read the error, fix it, and run the SUnit tests until they pass.
  • Answer questions about the code in your image with facts it looked up instead of guesses.

Run the reference agent

The pharo-one package ships an agent whose tools run in real headless Pharo images:

pip install "pharo-one @ git+https://github.com/pharo-llm/pharo-one"
ollama pull pharo-llm/pharo-coder:mini
pharo-one agent --config configs/pharo-coder-1.0-mini.yaml --model pharo-llm/pharo-coder:mini \
  "Create a class ShoppingCart with add:, removeAll:, total, and an SUnit test class. Make the tests pass."

Each step is printed: the model's reasoning, every tool call, and the Pharo result. At the end you get the complete code that was built and verified in the session. Example of a real run:

→ define {"code": "Integer >> isPalindromicNumber\n\t^ self asString = self asString reverse"}
Defined: Integer>>isPalindromicNumber

→ evaluate {"code": "12321 isPalindromicNumber"}
true

Pharo-Coder: I added isPalindromicNumber to Integer and verified that 12321 isPalindromicNumber returns true.

Tools

ToolArgumentsWhat it does
evaluatecodeEvaluate Pharo code in the image (with everything defined so far); returns the printString or the error.
definecodeCreate or update classes and methods (fluid class syntax, ClassName >> selector); returns compile errors.
browse_classclass_nameClass definition, comment and selectors (instance and class side).
method_sourceclass_name, selectorSource of a method (append class for class-side).
implementorsselectorMethods implementing a selector in the image.
sendersselectorMethods sending a selector in the image.
search_classesqueryClasses whose name contains a substring.
run_testsclass_nameRun an SUnit TestCase subclass and report failures and errors.

Every tool call starts a fresh image and replays the definitions made so far in the session, so runs are isolated and reproducible and nothing touches your own image.

Use your own tools

Pharo-Coder uses the standard Qwen2.5 / Hermes tool-calling format, so any OpenAI-compatible client with tools works with Ollama or vLLM:

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
tools = [{"type": "function", "function": {
    "name": "evaluate",
    "description": "Evaluate Pharo code and return the printString of the result",
    "parameters": {"type": "object", "properties": {"code": {"type": "string"}}, "required": ["code"]}}}]
messages = [{"role": "user", "content": "What is 2 raisedTo: 100 in Pharo? Check it."}]

while True:
    msg = client.chat.completions.create(model="pharo-llm/pharo-coder:mini", messages=messages, tools=tools).choices[0].message
    messages.append(msg)
    if not msg.tool_calls:
        print(msg.content)
        break
    for call in msg.tool_calls:
        result = run_in_pharo(call)          # your implementation
        messages.append({"role": "tool", "tool_call_id": call.id, "content": result})

With vLLM, start the server with --enable-auto-tool-choice --tool-call-parser hermes.

How the agent was trained

A teacher model solved thousands of tasks in this exact tool loop against real Pharo images. A trajectory was used for training only if the code it built passed hidden unit tests in strict mode (no unknown selectors, examples run), or, for exploration questions, if the answer stated the fact it looked up. Tool outputs are never trained on; only the model's own decisions and answers are. Agent ability is measured on PharoEval-Agent and is part of the release gate.
