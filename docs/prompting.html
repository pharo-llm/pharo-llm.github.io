Use the models

Prompting guide

Pharo-Coder was trained on precise, test-backed tasks. Prompts that look like that get the best answers.

Name things

Give the class name, superclass, and the selectors you want. "Create ParkingGarage with park:, leave: and freeSpots" beats "make a parking program".

State edge cases

Say what must happen on empty collections, invalid input, or limits ("pop on an empty stack signals an Error"). The model was trained on tasks whose tests cover edge cases and follows them closely.

Paste errors verbatim

For debugging, paste the code and the exact error or debugger message (e.g. MessageNotUnderstood: receiver of "+" is nil). Pharo-Coder was trained on real Pharo error messages produced by running wrong code.

Ask for tests

"Also write an SUnit TestCase subclass" produces tests in the standard assert:equals: / should:raise: style.

Ask questions

You can ask conceptual questions ("When should I use a Trait?", "How does ensure: differ from ifCurtailed:?") and how-to questions about tools like Iceberg and Metacello. For questions about your image, use the agent so it can look things up instead of guessing.

Output format

By default answers use the canonical format below, which you can paste into a browser piece by piece. Ask for "Tonel format" if you want a file to load with Iceberg.

Object << #LimitedStack
	slots: { #items . #capacity };
	package: 'MyApp'

LimitedStack class >> new: anInteger
	^ self new setCapacity: anInteger

LimitedStack >> push: anObject
	self isFull ifTrue: [ ^ self error: 'stack is full' ].
	^ items addLast: anObject

System prompt

The models are trained with this system prompt (already built into the official Ollama models and chat template):

You are Pharo-Coder, an expert Pharo Smalltalk engineer. Write correct, idiomatic, runnable Pharo code (Pharo 12+). Define classes with the fluid syntax `Superclass << #Name slots: { #a }; package: 'Pkg'` and write each method as `ClassName >> selector` followed by its body. Put code in ```smalltalk fences.
